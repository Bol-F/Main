# Python Job Interview Preparation

This guide lists what a beginner Python developer should prepare before applying for internships, junior roles, or entry-level backend/data automation jobs.

## Interview Areas

Most beginner interviews test five things:

1. Python fundamentals.
2. Problem solving with simple data structures.
3. Ability to read errors and debug.
4. Basic developer tools such as Git, terminal, and virtual environments.
5. Ability to explain a project clearly.

## Python Questions To Practice

- What is the difference between `list`, `tuple`, `set`, and `dict`?
- When would you use a dictionary instead of a list?
- What does it mean for a value to be mutable?
- Why can `grades=[]` as a function or method default argument be dangerous?
- What is the difference between `==` and `is`?
- What is the difference between `append`, `extend`, and list concatenation?
- How does slicing work?
- What does `range(2, 10, 2)` produce?
- What is a function return value?
- What is variable scope?
- What are `*args` and `**kwargs`?
- Why should you catch specific exceptions instead of using bare `except`?
- What does `with open(...)` do?
- What is a module?
- What is the difference between a class and an object?
- What are inheritance, encapsulation, polymorphism, and abstraction?
- What is Big O notation?

## Coding Problems To Practice

Start with these until they feel natural:

1. Reverse a string without using `[::-1]`.
2. Check if a string is a palindrome.
3. Count how many times each word appears in a sentence.
4. Find the largest and smallest number in a list.
5. Remove duplicates from a list.
6. Find duplicate values in a list.
7. Check if two strings are anagrams.
8. Implement FizzBuzz.
9. Find the second largest number in a list.
10. Merge two sorted lists.
11. Use binary search on a sorted list.
12. Validate balanced parentheses with a stack.
13. Read a file and count lines, words, and characters.
14. Parse a CSV file and calculate totals.
15. Build a simple calculator with error handling.

## Problem Solving Routine

Use this structure in interviews:

1. Repeat the problem in your own words.
2. Ask about edge cases.
3. Write one or two examples.
4. Explain a simple approach first.
5. Code slowly with clear variable names.
6. Test the code with normal and edge cases.
7. Explain time and space complexity if asked.

## Edge Cases To Remember

- Empty input.
- One item only.
- Duplicate values.
- Negative numbers.
- Zero.
- Uppercase vs lowercase strings.
- Extra spaces in user input.
- Division by zero.
- Missing dictionary keys.
- Missing files.

## Developer Skills Employers Expect

Even for beginner roles, you should know the basics of:

- Terminal commands: `cd`, `dir` or `ls`, running Python scripts.
- Virtual environments: why projects should isolate dependencies.
- `pip`: installing and freezing packages.
- Git: branch, add, commit, push, pull, merge, and pull request.
- GitHub: readable README files and clean project history.
- Testing: writing simple tests for functions.
- Debugging: reading tracebacks and finding the exact failing line.
- SQL: select rows, filter rows, join tables, and aggregate data.
- APIs: HTTP methods, status codes, JSON, and basic authentication concepts.

## Project Story Template

Prepare this for each project on your resume:

- Problem: What did the project solve?
- Users: Who would use it?
- Features: What can it do?
- Technical choices: Why did you use files, JSON, SQLite, an API, or classes?
- Hard part: What bug or design problem did you solve?
- Improvement: What would you add next?

## Behavioral Questions

Practice short answers for:

- Tell me about yourself.
- Why do you want this role?
- Tell me about a time you were stuck.
- How do you learn a new topic?
- Tell me about a bug you fixed.
- How do you handle feedback?
- What project are you most proud of?

## What To Show On GitHub

Each portfolio project should include:

- A clear `README.md`.
- How to run the project.
- Example input and output.
- A short feature list.
- At least a few meaningful commits.
- Clean names and small functions.
- Tests for important logic when possible.

## Final Mock Interview Checklist

Before applying, do at least three mock interviews:

- One focused on Python basics.
- One focused on coding problems.
- One focused on your projects and behavioral questions.

After each mock interview, write down what went wrong and practice those weak areas again.
